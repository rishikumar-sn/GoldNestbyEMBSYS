LAN ENCRYPTION — REQUIRED
==============================================================

The user explicitly requested encrypted data exchange.

Do NOT simply use plain HTTP for the release APK.

Implement LAN TLS.

Create:

    backend/scripts/generate_lan_certificate.py

It should generate:

    backend/certs/server.crt
    backend/certs/server.key

Use a cryptographically secure key.

Private key NEVER leaves backend PC.

The Flutter application must use certificate pinning.

IMPORTANT SECURITY RULE:

Do NOT implement this:

    badCertificateCallback = (...) => true

That would make TLS effectively vulnerable to MITM.

If a custom certificate callback is required for the self-signed LAN certificate,
accept the certificate ONLY when its SHA-256 fingerprint exactly matches the
configured/pinned server certificate.

Provide a build/setup process that:

    server.crt
        ↓
    compute SHA-256 fingerprint
        ↓
    include trusted fingerprint/certificate in Flutter build assets/config

The private key must NEVER be included in Flutter.

Allow insecure HTTP only through an explicit development configuration such as:

    ALLOW_INSECURE_HTTP=true

Release mode must default to false.

==============================================================
YOLOE
==============================================================

Use YOLOE open-vocabulary INSTANCE SEGMENTATION as primary jewellery separation.

Start with:

    yoloe-26s-seg.pt

unless compatibility/environment inspection shows a justified reason to select
another official YOLOE segmentation checkpoint.

Text prompting is the first strategy.

Make prompts configurable.

Initial prompt configuration may use:

    jewelry
    gold jewelry

Do NOT use YOLOE class label as the final jewellery type.

YOLOE's job is:

    find physical jewellery instances
    segment jewellery
    count physical pieces

SigLIP determines jewellery type.

Model downloading/preparation must use the official Ultralytics mechanism.

IMPORTANT:

Text-prompted YOLOE also requires its text encoder resources.

The download/preparation script must perform a one-time model initialization and
text prompt preparation so that all required text encoder assets are downloaded
BEFORE normal server operation.

Keep YOLOE model/text resources under:

    backend/models/yoloe/

or backend/models/_cache/

Do not leave random downloaded model resources scattered throughout the repository
or user home directory.

If Ultralytics APIs force caching elsewhere, explicitly configure/cache/document it.

    keep/merge the best physical instance

==============================================================
INSPYRENET
==============================================================

Use InSPyReNet as:

    1. mask refinement when YOLOE finds an object but mask quality is poor
    2. full-image fallback when YOLOE fails to locate jewellery

Use the official InSPyReNet/transparent-background implementation.

Default V1 checkpoint:

    ckpt_fast.pth

Store it:

    backend/models/inspyrenet/ckpt_fast.pth

Provide OPTIONAL support for:

    ckpt_base.pth

but do not require the heavier model for V1.

Download from the official plemeri Hugging Face/repository source using the model
download script.

Use the supported Python API rather than shelling out to a CLI for every request.

The integration should be conceptually:

    Remover(
        mode="fast",
        device=...,
        ckpt=<local checkpoint>
    )

and return a saliency/alpha mask that our own service post-processes.


==============================================================
YOLOE → INSPYRENET PIPELINE
==============================================================

For an uploaded image:

    ORIGINAL HIGH-QUALITY IMAGE
                ↓
    create inference-size copy
                ↓
    YOLOE TEXT-PROMPT SEGMENTATION
                ↓
    deduplicate instances
                ↓
    validate masks
                ↓
       ┌────────┴────────┐
       │                 │
    good mask        poor mask
       │                 │
       │        crop original-resolution ROI
       │           with padding
       │                 ↓
       │          InSPyReNet fast
       │                 ↓
       │          refined foreground
       │                 │
       └────────┬────────┘
                ↓
          FINAL INSTANCE MASK


If YOLOE returns no valid instances:

    full image
       ↓
    InSPyReNet fast
       ↓
    binary/saliency mask
       ↓
    connected components
       ↓
    filter noise
       ↓
    conservative component grouping
       ↓
    fallback jewellery instances

IMPORTANT:

InSPyReNet is not true instance segmentation.

Therefore results derived from the full-image fallback must record:

    segmentation_source = "inspyrenet_full_fallback"

and counting confidence should be lower.

Do not pretend an InSPyReNet connected-component count is equally reliable to
YOLOE instance segmentation.


==============================================================
MASK QUALITY VALIDATION
==============================================================

Avoid assumptions that break bangles/rings.

For example, do NOT reject a bangle simply because the foreground occupies a low
percentage of its rectangular bounding box.

Use conservative checks such as:

    mask exists
    mask area above absolute/relative minimum
    detection confidence
    extreme full-frame mask
    severe fragmentation
    invalid coordinates
    obviously tiny noise

All thresholds must live in configuration, not be spread as magic constants.


==============================================================
CROP CREATION
==============================================================

For every final jewel instance:

1. return to ORIGINAL high-resolution image
2. use final full-resolution mask
3. find tight bounding box
4. add configurable padding
5. extract jewel
6. preserve alpha/mask copy
7. composite onto WHITE background
8. square-pad while preserving aspect ratio

Generate:

    original crop
    mask
    transparent PNG if useful
    standardized white-background classification image

The standardized white-background image becomes the SigLIP input source.

Do NOT alter the actual jewellery pixels unnecessarily through:
    excessive saturation
    artificial gold enhancement
    heavy CLAHE
etc.
